# Защиты монитора после аудита

1. **STOP / SIGINT / SIGTERM.** Проверка до запуска, между итерациями, до и после стакана. Паузы опроса/backoff прерываются с шагом до 250 мс. Уже выполняющийся HTTP-запрос ограничен timeout, мгновенное прерывание запроса не обещается.
2. **HTTP backoff.** Ограниченные попытки при сетевых ошибках, 429/418/5xx. `Retry-After` в секундах или HTTP-date соблюдается без сокращения до backoff_max. Нет обхода блокировок или смены IP.
3. **Парсинг.** Некорректная структура CMS пропускается; нечисловые даты не становятся сигналами. Переименование полей требует обновления парсера. Длительное отсутствие валидной ленты отмечается `FEED UNHEALTHY` в логе, внешних уведомлений нет.
4. **Фьючерсная ликвидность.** Только fapi, без спотового fallback. Для входа в шорт суммируются bids в заданной полосе от mid. NaN/Inf, отрицательные объёмы, пересечённый или неотсортированный стакан отклоняются. Проверка стакана не гарантирует исполнения.
5. **Часы.** HTTP-оценка offset и RTT. Старые и слишком будущие новости отклоняются. Наблюдения включают `clock_synced`, поскольку при недоступном time endpoint остаётся время локального хоста. Это не измерение с точностью NTP.
6. **Состояние.** Bootstrap без исторических сигналов, атомарная замена курсора, ограниченный список ID. Повреждённый файл повторно bootstrap-ится. Чтение после получения lock. Между логом и сохранением нет транзакции: авария в этом промежутке может повторить наблюдение.
7. **Один процесс.** POSIX flock; второй процесс не затирает PID первого. Поддерживается macOS/Linux.
8. **Наблюдения.** `logs/observations.jsonl`: ID/code, release/detected timestamp, лаг, clock offset/RTT/status. Время обнаружения всей пачки фиксируется до запросов стаканов. Bootstrap не включается в измерения. JSONL нужно периодически архивировать; основной текстовый лог ротируется.

`SIGNAL PAPER` не исполняет ордеров. Нет P&L, бумажных позиций, доставки алертов или гарантии отсутствия пропущенных новостей: API запрашивается одной страницей. TTL из исторических зондов не является универсальной задержкой; фактический лаг следует измерять по новым наблюдениям.

Проверки: `python selftest_monitor.py`, `python -m unittest discover -s tests -v`. Сетевые selftests запускаются отдельно через `--live`.
