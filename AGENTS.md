# AGENTS.md — контекст проекта для ИИ-агента

Ты работаешь с репозиторием, который отвечает на один вопрос и уже довёл его до
вывода. Не нужно ничего заново реверсить — прочитай это целиком, и ты поймёшь,
что здесь происходит и что именно проверялось.

## Вопрос, на который отвечает репо

**Можно ли устойчиво зарабатывать, шортя токен в момент анонса его делистинга
с Binance, начиная с $1 000 при риске ~1% на сделку?**

## Короткий ответ (вывод, к которому всё свелось)

**Нет.** Эдж существует и он большой, но он чисто скоростной: умирает за ~30
секунд после анонса. Бесплатный канал Binance отдаёт анонс с задержкой 55–130
секунд (кэш CloudFront), поэтому эдж недостижим. Все обходные пути проверены и
закрыты (Telegram медленнее, другие биржи следуют за Binance, диверсификация не
спасает от жирного хвоста). Даже будь лаг решён, при $1 000 экономика не
сходится: потолок ~$15–30/мес, что ниже стоимости любого платного фида.

## Ключевые цифры (проверенные, не оценки)

| Факт | Значение |
|---|---|
| Торгуемых событий (фьючерс был + объём до анонса) | 115 за 4.7 года (≈2/мес) |
| Эдж на тиках, вход через 1 с (среднее net, стоп 1%, горизонт 5м) | +434 бп, 95% ДИ [+305; +570] |
| вход 5 с | +147 бп [+59; +255] |
| вход 15 с | +77 бп [+1.4; +172] |
| вход 30 с | +2.6 бп [−40; +52] — значимость исчезает |
| вход 130 с | +32 бп [−11; +79] |
| TTL кэша CloudFront (pageSize=1 / pageSize=10) | 111 с / 252 с |
| Реальный лаг обнаружения | 55–130 с |
| Telegram против CMS (280 событий, точный code) | всегда позже, медиана +120 с |
| Bybit perpetual-делистинги против Binance (8 пар) | Bybit позже в 6/8, медиана +35 ч |

## Словарь терминов, чтобы не перечитывать по 2 раза

- **bps / бп** — базисный пункт, 1 бп = 0.01%. `net_bps` = движение минус комиссия
  (по умолчанию 10 бп round trip).
- **лаг / lag** — время от публикации анонса до момента входа в позицию.
- **шорт (short)** — прибыль при падении цены. Шортить можно **только фьючерс**,
  спот шортить нельзя (нет займа) — это критично и часто нарушается.
- **USDⓈ-M перпетуал** — бессрочный фьючерс Binance с маржой в стейблкоинах.
- **CloudFront TTL** — время жизни объекта в кэше CDN; пока оно не истекло, API
  отдаёт устаревший снимок. Заголовок `age` показывает точный возраст снимка.
- **бутстрэп ДИ** — 95% доверительный интервал среднего через пересэмплирование
  (seed=42, детерминировано). Интервал накрывает ноль = результат неотличим от шума.
- **ликвидация** — капитал не может уйти в минус; убыток больше счёта = счёт умер.
- **отрицательная асимметрия** — медиана положительная, но среднее отрицательное:
  редкий катастрофический хвост перевешивает частые мелкие выигрыши.

## Логическая цепочка (это и есть «что надо понять»)

1. Делистинг фьючерса — жёсткий механизм: контракт прекращает торговаться, цена
   обычно падает. Направление известно → вопрос только в скорости.
2. Тиковый бэктест (`tick_backtest.py`) показал: движение происходит в первые
   секунды, к 30 с от него почти ничего не остаётся. Эдж = чистая латентность.
3. Наш канал — Binance CMS за CloudFront — отдаёт данные не свежее TTL (111–252 с),
   и это нельзя обойти (обход кэша = 429 + блок ~5 мин).
4. Альтернативные источники медленнее или равны: Telegram (+120 с), Bybit
   (следует за Binance по перпетуалам).
5. Медленный вариант (держать шорт дни, диверсифицировать) упирается в хвост:
   один пампинг токена (ALPACA +847% против шорта) перечёркивает десятки выигрышей.
6. Экономика: даже +77 бп на $1 000 при риске 1% и 2 событиях/мес ≈ $15/мес —
   меньше стоимости любого платного канала. Вывод: депозит не оправдан.

## Структура репозитория

### Воспроизводимые измерения эджа
- `tick_backtest.py` — главный прогон. Качает тики с `data.binance.vision`
  (официальный архив), считает затухание эджа по лагу + бутстрэп ДИ. Входной
  манифест — `data/events.json`.
- `backtest_futures.py` — сетка лаг×стоп×горизонт на 1-минутных фьючерсах.
  Только фьючерсы (спот исключён), компаундинг, ликвидация счёта.
- `horizon_test.py` — медленные горизонты до 7 дней.
- `analyze_edge.py` — распределение сделок, концентрация прибыли (топ-5 доля).
- `split_by_type.py` — деление анонсов по типу (фьючерсы/маржа/спот/alpha).
- `tg_lag.py` — лаг Telegram против CMS (сопоставление по точному `code` статьи).
- `lead_lag.py` — кто раньше объявляет делистинг: Bybit или Binance.

### Замеры инфраструктуры (зависят от региона/времени)
- `probe_ratelimit.py`, `probe_ttl.py`, `probe_ttl2.py`, `probe_ttl_variants.py` —
  лимиты запросов и TTL кэша CloudFront.

### Монитор (НЕ торгует)
- `monitor.py` + `monitor_core.py` — слушатель анонсов, пишет `SIGNAL PAPER` и
  `detect_lag` в лог. Ордеров не отправляет — ни реальных, ни бумажных.
- `selftest_monitor.py` — 26 проверок.

### Документация
- `VERIFICATION.md` — **главный файл**: 7 пронумерованных утверждений, у каждого
  команда воспроизведения и ожидаемое число. С него начинай проверку.
- `BACKTEST_RESULTS.md` — все таблицы и полный ход рассуждения.
- `PROTECTIONS.md` — защиты монитора и измеренные лимиты/латентность.

### Данные (`data/`)
- `events.json` — манифест 115 торгуемых событий (symbol + release_ms).
- `cms_articles.json` — статьи каталога 161 (делистинги) и 48 (листинги).
- `*.json` с результатами (`tick_backtest.json`, `fut_backtest*.json`,
  `horizon_test.json`, `tg_lag.json`, `lead_lag.json`, зонды).

## Ловушки — что НЕЛЬЗЯ делать и во что НЕЛЬЗЯ верить

1. **`backtest_delist.py` и `data/delist_backtest.json` недействительны.** Они
   запрашивали у фьючерсов `interval=1s`, а такого интервала нет (HTTP 400,
   `code -1120`) — код молча падал в спот. Результат (+$14 496) посчитан по
   спот-ценам, которые нельзя шортить. Оставлены только как след ошибки.
2. **«+$101 016 на $1 000» — артефакт компаундинга**, а не цель. Возникает из-за
   роста капитала на 4.3%/сделку при лаге 1 с (профиль co-located бота). Не
   подавай это как достижимый результат.
3. **Спот ≠ фьючерс.** Любая стратегия, опирающаяся на спот-цены делистинговых
   пар, физически неисполнима (шорт невозможен).
4. **Большие кэши не в git** (`fut_klines_long.json`, `tick_windows.json`,
   `delist_klines.json`) — их перекачивают скрипты из первоисточников.
5. **Не подгоняй параметры на 115 событиях** — это переобучение. Любой новый
   «эдж» обязан пройти тот же стандарт: тики из первоисточника, реалистичная
   комиссия, модель лага, бутстрэп ДИ, out-of-sample.

## Как воспроизвести

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt   # единственная зависимость — httpx
python tick_backtest.py           # главный прогон (~10 мин, качает тики сам)
python tg_lag.py --pages 60
python lead_lag.py
python horizon_test.py
```

## Границы того, чего в репо НЕТ

- Нет исполнения ордеров (ни реальных, ни бумажных).
- Нет live P&L — ни одна цифра доходности не проверена на живых деньгах.
- Нет API-ключей Binance — только публичные read-only эндпоинты.
- Нет paid-подписок; всё на бесплатных источниках.
