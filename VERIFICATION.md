# Воспроизведение и статус проверки

Дата аудита: 30.10.2026. Исторические цифры не считаются эталоном после исправления модели.

## Локальные проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python selftest_monitor.py
.venv/bin/python audit_research.py
.venv/bin/python build_manifest.py
```

Получено: **18 регрессионных тестов + 23 офлайн-проверки монитора пройдены**. Дополнительно выполнен `selftest_monitor.py --live`: **26/26**, включая время Binance, фьючерсный стакан BTCUSDT и отказ для несуществующего символа. Это проверяет доступность этих API из текущей сети, не прибыльность стратегии.

Аудит сохранённых данных:

- `events.json`: 115 уникальных symbol × timestamp, 74 timestamp публикации, 93 символа.
- Все timestamp манифеста найдены в сохранённом каталоге CMS 161; это проверка связи по времени, не полная верификация содержания каждой статьи.
- Исходный `tick_backtest.json`: только 2 события, 0 строк доверительных интервалов.
- В минутном кэше 126 непустых рядов, из которых 115 имеют нужные данные до/после публикации.
- `candidate_audit.v2.json`: 115 кандидатов с данными, 11 без объёма до публикации, 242 с пустым старым кэшем, 227 не загружены. Кандидаты извлечены из заголовков и могут включать ошибочные тикеры. Пустой кэш не отличает отсутствие контракта от ошибки API.

`data/audit_v2.json` содержит SHA-256 входов и новую минутную сетку. Исторический манифест не расширен непроверенными кандидатами.

## Полный тиковый пересчёт

```bash
.venv/bin/python tick_backtest.py
```

Публичные архивы Binance загружены по всем **115/115** событиям исторического манифеста. Новый отчёт: `data/tick_backtest.v2.json`. Сырые окна в `data/tick_windows.json` (не включаются в git). `--refresh` скачивает заново. Повтор из сохранённых окон использует те же данные и детерминированный seed.

Параметры: стоп 100 бп, горизонт 300 секунд **от публикации**, фиксированные расходы 10 бп. Бутстрэп: 2000 повторов, seed 42, ресэмплирование 74 кластеров публикаций с сохранением токенов каждой новости. Среднее взвешено по символам-событиям, а не поровну по публикациям.

| Задержка, сек | Среднее net, бп | 95% кластерный ДИ, бп |
|---:|---:|---:|
| 1 | 543,4 | [355,7; 741,7] |
| 5 | 143,4 | [44,8; 259,8] |
| 15 | 75,8 | [−6,5; 172,8] |
| 30 | 1,3 | [−48,4; 56,7] |
| 60 | 77,1 | [14,3; 149,7] |
| 111 | 11,9 | [−29,0; 58,1] |
| 130 | 40,4 | [−6,3; 95,3] |
| 252 | −7,8 | [−32,1; 21,4] |

Это **исследовательские интервалы по всем событиям**, без поправки на перебор конфигураций и без независимой будущей выборки. Результат при 60 секундах не позволяет утверждать монотонное исчезновение эффекта на точной границе 30 секунд. Стоп исполняется по наблюдаемой сделке, но исполнимость объёма по этой цене не подтверждена.

Поле `grid` — другая выборка: условный портфель с одной позицией, пересекающиеся сделки пропускаются. Например, при lag=130, stop=100, h=300: 74 сделки, 41 пропуск по пересечению, условный P&L **+$132,86 за весь исторический период**, максимальная просадка модели 14,24%. Это не прогноз доходности и не результат исполнения на бирже. Нельзя смешивать среднее этого портфеля с ДИ всех 115 событий.

## Сохранение результатов

- Полный запуск: `tick_backtest.v2.json`.
- `--limit N`: `tick_backtest.v2.sample.json`, не перезаписывает полный отчёт.
- При недоступных данных: `tick_backtest.v2.partial.json`.
- `--output PATH` задаёт явный файл.
- `--cost BPS` задаёт фиксированные расходы; дополнительные рыночные издержки автоматически не оцениваются.
- Минутные и длинные отчёты сохраняются отдельно с `.v2`; многодневный архив в этой проверке не перекачивался. Его исправленная симуляция проверена граничными тестами, прежние многодневные суммы не подтверждены повторным прогоном.

## Источники и ограничения

Архив сделок: [Binance Public Data](https://github.com/binance/binance-public-data). Структура минутных свечей и отдельные open/close timestamp: [Binance Kline/Candlestick Data](https://developers.binance.com/docs/derivatives/usds-margined-futures/market-data/rest-api/Kline-Candlestick-Data). Механика кэширования: [CloudFront expiration](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/Expiration.html).

Исторические замеры TTL, Telegram и Bybit не были повторены как синхронный живой эксперимент. Они не доказывают универсальную задержку бесплатных источников. Реальные ордера, funding, стакан исполнения и liquidation engine не проверялись. Полный разбор: [AUDIT.md](AUDIT.md).
